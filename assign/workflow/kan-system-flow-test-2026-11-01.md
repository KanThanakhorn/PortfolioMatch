# ผลทดสอบ System Flow และ Integration ของกานต์

วันที่: 1 พฤศจิกายน 2569
Branch: `kan/backend` หลัง merge `023cdc9`
สภาพแวดล้อม: Next.js dev server บน `localhost:3000`, Google Chrome 156.0.8078.79 แบบ headless, ข้อมูลทดสอบแยกอยู่ในโปรไฟล์เบราว์เซอร์ชั่วคราว

| กรณีทดสอบ | ผล | สิ่งที่ตรวจพบ |
|---|---|---|
| กรอกชื่อรอบ, requirement และคำถาม แล้วสร้างลิงก์ | Pass | ลิงก์มีค่าที่กรอก และฟอร์มผู้สมัครแสดงชื่อรอบกับคำถามใหม่ |
| เลือกไฟล์ `.txt` | Pass | แจ้ง “เลือกไฟล์ PDF เท่านั้น”, ล้างไฟล์, จำนวนผู้สมัครไม่เพิ่ม |
| เลือกไฟล์ `.pdf` ขนาด 51 MiB | Pass | แจ้ง “ไฟล์ต้องไม่เกิน 50 MB”, ล้างไฟล์, จำนวนผู้สมัครไม่เพิ่ม |
| กรอกข้อมูลครบและเลือก PDF แล้วส่ง | Pass | สร้างผู้สมัครใหม่พร้อมเลขอ้างอิงและชื่อไฟล์ PDF ในข้อมูลเดโม |
| รีเฟรชหน้าสำเร็จ | Pass | เลขอ้างอิงเดิมยังแสดงใน session เดียวกัน |
| Approve ผู้สมัครใหม่ แล้วรีเฟรชรายละเอียด | Pass | สถานะยังเป็น Approved |
| Reject ผู้สมัครตัวอย่าง แล้วรีเฟรชรายละเอียด | Pass | สถานะยังเป็น Rejected |
| เปิด Applicants และ Dashboard | Pass | ทั้งสองหน้าแสดงชื่อและสถานะ Approved/Rejected ตรงกัน |
| TypeScript และ production build | Pass | `npm run typecheck` และ `npm run build` สำเร็จ |

การทดสอบการส่งใช้ไฟล์ PDF ที่สร้างในเบราว์เซอร์เพื่อยืนยัน flow ฝั่งหน้าเว็บ. แอปตรวจชนิดและขนาดไฟล์แล้วบันทึกเพียงชื่อไฟล์ใน `localStorage`; ไม่ได้ส่งเนื้อไฟล์ไป server. ผลการคงอยู่ของข้อมูลใช้ได้เฉพาะ origin และโปรไฟล์เบราว์เซอร์เดียวกัน. การทดสอบมือถือ 390×844 ของป้ายสถานะ Applicants/Dashboard บันทึกไว้ใน `qa-report-review.md`; ยังควรให้ตงเก็บภาพหลักฐานบนเบราว์เซอร์เป้าหมายและทดสอบ responsive ทุกส่วนก่อนปิด QA.
