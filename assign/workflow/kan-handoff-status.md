## สิ่งที่ทำแล้วและสาธิตได้

| งาน | สถานะ | หลักฐาน/วิธีสาธิต |

| วิธีรัน/Architecture/เทคโนโลยี | ทำเอกสารแล้ว | `assign/workflow/kan-implementation.md`; `npm run dev`, Next.js App Router, React, TypeScript, localStorage |
| Build และ typecheck | ผ่าน | `npm run typecheck` และ `npm run build` exit 0 หลัง merge ตง |

## สิ่งที่ยังไม่ครบ

1. **แชร์ลิงก์ให้ผู้สมัครคนละเครื่อง:** ข้อมูล campaign และใบสมัครอยู่ใน localStorage ของแต่ละเบราว์เซอร์ จึงไม่ซิงก์ข้ามเครื่องหรือบัญชี. ต้องมี backend/database จึงจะเป็น flow รับสมัครจริง.
2. **อัปโหลดและเปิด Portfolio จริง:** ปัจจุบันตรวจไฟล์ตอนเลือกและบันทึกเพียงชื่อไฟล์. ไม่มี file storage หรือ URL สำหรับกรรมการเปิดต้นฉบับ.
3. **AI วิเคราะห์ Portfolio จริง:** คะแนนและข้อความของผู้สมัครตัวอย่างเป็น mock; ไม่มี inference pipeline หรือผลวิเคราะห์ของผู้สมัครใหม่.
4. **รอบรับสมัครหลายรายการ:** หน้าสร้างรอบแก้ข้อมูล campaign เดียวและใช้ URL เดียว; เมื่อแก้ requirement ผู้สมัครเก่าก็เห็น requirement ล่าสุด.
5. **Functional Test หลังแก้ครบทุกกรณี:** ยังไม่มีหลักฐานทดสอบ Reject หลังรีเฟรช, ไฟล์ผิดชนิด/เกินขนาด, และ responsive ทุกส่วน. รายงาน QA ของตงลงวันที่ 30 ต.ค. เป็น baseline ก่อนการแก้และไม่มี screenshot.
6. **ปุ่มรอง:** Settings และแจ้งเตือนยังไม่มีฟังก์ชัน.

## ข้อมูลสำหรับตง

- ใช้ `assign/workflow/qa-report-review.md` เป็นรายการ retest หลัง merge.
- ทดสอบบน origin/เบราว์เซอร์เดียวสำหรับ flow อาจารย์และผู้สมัคร; บันทึก Pass/Fail, browser/version, screenshot และ issue ที่ยังเปิด.
- ทดสอบทั้ง Approve และ Reject, ส่ง PDF ถูกต้อง/ผิดชนิด/เกิน 50 MB, รีเฟรชหน้าสำเร็จ, และมือถือ 390×844 จนสุดหน้า.
- อย่าใช้รายงาน 30 ต.ค. เป็นผลยืนยัน branch ปัจจุบันโดยไม่ทดสอบซ้ำ.

## ข้อมูลสำหรับนัท

- อธิบายผลงานเป็น **interactive prototype**: สร้างรอบตัวอย่าง กรอกใบสมัคร จำลองการแนบ PDF และการตัดสินใจของกรรมการ.
- นำ User Flow, Mermaid Architecture Diagram, เทคโนโลยี และผล build จาก `kan-implementation.md` ไปใช้ในรายงาน.
- ระบุข้อจำกัดตามจริง: ไม่มี backend/database, เก็บข้อมูลเฉพาะในเบราว์เซอร์, ไม่เก็บไฟล์ PDF, ไม่ส่งอีเมล, ไม่วิเคราะห์ AI จริง.
- ในสไลด์/รายงาน อย่าใช้คำว่า “อัปโหลด Portfolio สำเร็จ” หรือ “AI วิเคราะห์แล้ว” สำหรับใบสมัครใหม่.

## ลำดับเดโมที่ปลอดภัย

เปิด `/create` → สร้างลิงก์ → เปิด `/apply/ux-ai-2026` บนเบราว์เซอร์เดียวกัน → กรอกและเลือก PDF → ส่ง → ดู `/applications` → เปิดรายละเอียด → Approve/Reject → กลับ `/dashboard` ตรวจตัวเลข. ใช้ผู้สมัครตัวอย่างเพื่ออธิบายคะแนน mock และข้อจำกัด AI.

## เกณฑ์ปิดงานกานต์

ถ้าเป้าหมายคือ **เดโมต้นแบบบนเครื่องเดียว**: ต้องมีผล retest ของตงที่ผ่านสำหรับ flow สำคัญและแก้ defect ที่พบก่อนประกาศว่าครบ.  
ถ้าเป้าหมายคือ **ระบบรับสมัครที่ใช้หลายเครื่องจริง**: ต้องเพิ่ม backend, database, file storage, authentication และ AI pipeline ก่อนประกาศว่าครบ.
