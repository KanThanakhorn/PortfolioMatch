## สิ่งที่ยังไม่ครบ

1. **แชร์ลิงก์ให้ผู้สมัครคนละเครื่อง:** ข้อมูล campaign และใบสมัครอยู่ใน localStorage ของแต่ละเบราว์เซอร์ จึงไม่ซิงก์ข้ามเครื่องหรือบัญชี. ต้องมี backend/database จึงจะเป็น flow รับสมัครจริง.
2. **อัปโหลดและเปิด Portfolio จริง:** ปัจจุบันตรวจไฟล์ตอนเลือกและบันทึกเพียงชื่อไฟล์. ไม่มี file storage หรือ URL สำหรับกรรมการเปิดต้นฉบับ.
3. **ยืนยัน AI บนหน้าจอ:** endpoint Gemini ผ่านกับ PDF จำลองแล้ว (HTTP 200, คะแนนและหลักฐานครบ). ยังต้องส่งใบสมัครผ่านเบราว์เซอร์และตรวจว่าหน้ารายละเอียดแสดงผล AI ถูกต้องก่อนสาธิต.
4. **รอบรับสมัครหลายรายการ:** หน้าสร้างรอบแก้ข้อมูล campaign เดียวและใช้ URL เดียว; เมื่อแก้ requirement ผู้สมัครเก่าก็เห็น requirement ล่าสุด.
5. **QA บนหน้าจอและเบราว์เซอร์เป้าหมาย:** กานต์ทดสอบ flow หลัก, Reject หลังรีเฟรช และไฟล์ผิดชนิด/เกิน 50 MB แล้ว. ยังต้องให้ตงเก็บ screenshot และตรวจ responsive ทุกส่วนบนเบราว์เซอร์ที่ใช้สาธิต. PDF สรุปฉบับ 31 ต.ค. ระบุผลทดสอบเพิ่ม แต่ไม่มี PDF หลักฐานต้นทาง `_qa-roport.pdf` อยู่ใน repo นี้.
6. **ปุ่มรอง:** Settings และแจ้งเตือนยังไม่มีฟังก์ชัน.

## ข้อมูลสำหรับตง

- ใช้ `assign/workflow/qa-report-review.md` เป็นรายการ retest หลัง merge.
- ทดสอบบน origin/เบราว์เซอร์เดียวสำหรับ flow อาจารย์และผู้สมัคร; บันทึก Pass/Fail, browser/version, screenshot และ issue ที่ยังเปิด.
- ตรวจซ้ำ flow หลังแก้ CSS สถานะมือถือ โดยเฉพาะ Applicants และ Dashboard ที่ 390×844 จนสุดหน้า พร้อม screenshot.
- อย่าใช้รายงาน 30 ต.ค. เป็นผลยืนยัน branch ปัจจุบันโดยไม่ทดสอบซ้ำ.

## ข้อมูลสำหรับนัท

- อธิบายผลงานเป็น **interactive prototype**: สร้างรอบตัวอย่าง กรอกใบสมัคร จำลองการแนบ PDF และการตัดสินใจของกรรมการ.
- นำ User Flow, Mermaid Architecture Diagram, เทคโนโลยี และผล build จาก `kan-implementation.md` ไปใช้ในรายงาน.
- ระบุข้อจำกัดตามจริง: ไม่มี database, เก็บข้อมูลผู้สมัครและผล AI เฉพาะในเบราว์เซอร์, ไม่เก็บไฟล์ PDF, ไม่ส่งอีเมล. AI ส่ง PDF ไป Gemini เฉพาะเมื่อผู้สมัครยินยอม; endpoint ทดสอบจริงด้วย PDF จำลองแล้ว แต่ UI ยังต้อง retest.
- ในสไลด์/รายงาน แยกให้ชัดว่าแอปไม่เก็บไฟล์ Portfolio และผล AI จะเกิดขึ้นเฉพาะใบสมัครที่ยินยอมและวิเคราะห์สำเร็จ; อย่าอ้างว่าผู้สมัครใหม่ทุกคนผ่าน AI แล้ว.

## ลำดับเดโมที่ปลอดภัย

เปิด `/create` → สร้างลิงก์ → เปิด `/apply/ux-ai-2026` บนเบราว์เซอร์เดียวกัน → กรอกและเลือก PDF → ส่ง → ดู `/applications` → เปิดรายละเอียด → Approve/Reject → กลับ `/dashboard` ตรวจตัวเลข. ใช้ผู้สมัครตัวอย่างเพื่ออธิบายคะแนน mock และข้อจำกัด AI.

## เกณฑ์ปิดงานกานต์

ถ้าเป้าหมายคือ **เดโมต้นแบบบนเครื่องเดียว**: ส่วน System Flow ของกานต์ผ่านการทดสอบแล้ว; รอผล retest UI/responsive และภาพหลักฐานของตงก่อนปิด QA รวม.
ถ้าเป้าหมายคือ **ระบบรับสมัครที่ใช้หลายเครื่องจริง**: ต้องเพิ่ม database, file storage, authentication, rate limit และการประเมินคุณภาพ/ความเป็นธรรมของ AI ก่อนประกาศว่าครบ.
