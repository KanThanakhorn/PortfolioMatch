# การต่อ AI วิเคราะห์ Portfolio สำหรับเดโม

วันที่: 1 พฤศจิกายน 2569 · branch `kan/backend`

## Flow

1. ผู้สมัครกรอกข้อมูล เลือก PDF และเลือกช่องยินยอมให้ส่งไฟล์ไป OpenAI API.
2. ระบบบันทึกใบสมัครในเบราว์เซอร์ แล้วส่ง PDF กับ requirement ของรอบรับสมัครไปยัง `/api/analyze-portfolio`.
3. Route ฝั่งเซิร์ฟเวอร์ตรวจชนิดไฟล์ ขนาดต่ำกว่า 45 MB และลายเซ็น PDF ก่อนส่งไป Responses API. API key อยู่เฉพาะฝั่งเซิร์ฟเวอร์.
4. AI ตอบผลตาม JSON schema: คะแนนเสนอแนะ สรุป หลักฐานตามเกณฑ์ จุดแข็ง ข้อมูลที่ยังขาด และข้อจำกัด. ระบบบันทึกผลใน localStorage และแสดงในหน้ารายละเอียด.
5. กรรมการตรวจผลและตัดสิน Approve/Reject เอง. AI ไม่เปลี่ยนสถานะผู้สมัครอัตโนมัติ.

## การตั้งค่า

คัดลอก `.env.example` เป็น `.env.local` แล้วกรอก `OPENAI_API_KEY`. ค่าเริ่มต้นของโมเดลคือ `gpt-4.1-mini`; เปลี่ยนด้วย `OPENAI_MODEL` ได้. Production ปิด AI ไว้โดยค่าเริ่มต้น เพราะต้นแบบยังไม่มี authentication และ rate limit. ไม่ควรเปิด endpoint สาธารณะด้วย API key จนกว่าจะเพิ่มการควบคุมการใช้งาน.

## ผลตรวจและข้อจำกัด

- `npm run typecheck` และ `npm run build` ผ่าน.
- ทดสอบ route ด้วยผลตอบกลับ OpenAI จำลอง: แปลงผลเป็นคะแนนและหลักฐานได้, ปฏิเสธไฟล์ที่ไม่มีลายเซ็น PDF, และตอบข้อผิดพลาดเมื่อไม่ตั้งค่า key.
- ยังไม่มี API key ในสภาพแวดล้อมนี้ จึง **ยังไม่ได้ยืนยันผลวิเคราะห์จาก OpenAI จริง** หรือคุณภาพคะแนนกับ Portfolio ตัวอย่าง.
- PDF อาจมีข้อมูลส่วนบุคคล ผู้สมัครต้องยินยอมแยกก่อนส่งไฟล์. ใช้ข้อมูลจำลองสำหรับการสาธิต.
- ควรเปิดหน้าส่งใบสมัครค้างไว้จน AI ทำงานเสร็จ; หากรีเฟรชระหว่างวิเคราะห์ ระบบจะแจ้งว่าคำขอถูกขัดจังหวะ เพราะแอปไม่เก็บไฟล์ไว้สำหรับส่งซ้ำ.
- คะแนนเป็นคำแนะนำจากโมเดลและอาจคลาดเคลื่อน ต้องให้กรรมการตรวจต้นฉบับก่อนตัดสิน.
